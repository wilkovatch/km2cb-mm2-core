## Race containers and opponents

Races remain custom city properties with `elementContainer` metadata, category `race`. Their stable `_elementContainerId` is referenced by `_propertyContainerId` on owned custom elements and mesh settings. Keep MM2 eligibility and contextual commands in core JSON. The opponent is a Low Poly-only spline, with `placementObject: carModel`: the first click positions the independent parametric car, later clicks append waypoints. Its `difficulty` is 0 for amateur and 1 for professional. Preserve the professional fallback to amateur when the professional set is empty.

Migration 5 moves legacy opponent arrays into owned spline elements through the ordinary backup mechanism. `race_elements.py` adapts authored controls to the existing AIMAP/OPP writer and writes race-scoped props. The `race` property on PTH BIN parts carries the stable owner; `PATHSETWriter.write(output_path, race)` filters these separately from global props. `.km2-race-props.json` tracks only exporter-owned filenames for stale-file cleanup and is excluded from archives. Tests: `python exporters/psdl/tools/_test_races.py`, builder `KM2_SELFTEST_FOCUS=races`. Keep these checks short and synthetic.

Race difficulty editing uses nested property containers: `raceSetupAmateur` / `raceSetupProfessional` (and their Blitz variants) occupy the existing `policeCars` / `policeCars_professional` states. Their category is `raceDifficulty`, with parent category `race` and filtered inherited opponent membership (`difficulty` 0/1). Saved opponent owners remain the race identity; no exporter adapter or extra migration is needed. Do not reintroduce separate difficulty dropdowns for opponent or police creation. Shared checkpoints and props remain race-scoped. Focused builder coverage includes both difficulty selections, visibility, cancellation, presets, undo, clone and reload.

## Independent point values

Builder program version 5, feature version 1 saves non-anchorable leaves inline under `points`, with `position` and enabled `rotation`/`scale` vectors. `parkedCar`, `decalSingle` and `mapLabel` explicitly set `point.anchorable: false`; they have no shared point registry id and no M control-point editor. Migration 6 converts their saved centers before decoding, copies the saved world transform, preserves the original shared-point ids for other references, validates before writing, backs up the city/preferences and publishes coreVersion 6 last. The builder has no fallback for earlier referenced centers. Checks: `python exporters/psdl/tools/_test_independent_points_migration.py`, builder `KM2_SELFTEST_FOCUS=independentPoints`. The Lua geometry context and exporter JSON point shape stay the same.

## Instance state of the splines

The values of a road's spline (`project`, `projectAll`, `curveType`, `segments`, `segmentsPer100m`, `lpf`, `adjustLowPolyWidth`, `makeCoplanar`, `hermiteTension`, `subdivideEqually`), `warp` on roads and intersections, and `projectToGround` on building lines are in the instance state, so presets don't carry or change them. The initial values are in `elements/roads/*/settings.json` and `elements/buildings/psdl/line_settings.json`, and match what the templates used to set. `warp` on roads has `reuseInNewRoads`, so a road drawn in the editor takes it from the last road selected, with the spline values. Terrain patches keep `warp` and `projectToGround` in their state, because they have no presets. Spline custom elements keep these values in their single state, excluded from presets, and the decal's Bézier default moved from its preset to `spline.defaultCurveType`.

Migration 5 moves the values of the existing elements and removes them from the presets, only under the listed spline types for `customElement/<type>` (another type can have its own `segments`). A key that is missing stays missing, so it reads as before. Equivalence check: export an old city with the old build, migrate a copy, export again and compare PSDL, BAI and INST (0 differences expected). Checks: `python exporters/psdl/tools/_test_spline_state_migration.py`, builder `KM2_SELFTEST_FOCUS=splineState`.
