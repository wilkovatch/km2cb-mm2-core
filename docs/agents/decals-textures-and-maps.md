# Decals, textures and maps

Read the [repository instructions](../../AGENTS.md) first. Paths and command examples below are relative to this repository root unless another working directory is specified. Builder CLI and self-test commands run from the builder root.

Also read [Exporter workflow and engine limits](exporting.md). Independent decal/label points use the [point-state migration](races-and-state.md#independent-point-values); race-specific bridge maps are described in [Bridges](bridges.md).

## Native decal and map reference

**Decals (`city/<city>/decals.pathset`, PTH1):** one path per decal, named after its texture (≤ 31 chars). It is drawn as one triangle strip of point pairs, lifted +0.01 m. U is 0/1 alternating, and V of pair k = round(|p[2k]-p[0]| / |p[0]-p[1]|), so pairs must sit at about whole tile distances. The decal is attached to the room containing midpoint(p0, p2) and drawn only when that room is visible, so split long strips. Winding: ((p1-p0)×(p2-p0)).y > 0 in MM2 coordinates. Paths with fewer than 3 points are skipped.

**Hudmap and menu maps:** `geometry/hudmap_<city>.pkg` uses chunk `H` with FVF 0x102 and one quad per tile at y=0. **`.tex` rows are stored bottom-up**, so flip a north-up image before writing. `tune/<city>.mmHudMap` holds the `Ocean Color` as RGB 0..1. Menu maps are `jpg/<city>_map*.jpg`, 242x184, with the map in about (8,5)-(236,179). An optional frame goes in `Files/common/MidtownMadness2/jpg/mapframe.jpg`. Map labels appear only on the jpgs.

**Hudmap one-way arrows**, measured by correlating the stock tiles with `sf.bai` and `london.bai`: the head points with the traffic, towards the end of the road for the BAI left lanes (29 of 34 arrows in SF and 83 of 85 in London, counting those matched to a one-way road). They are baked in the art at a fixed size whatever the road: SF about 14 px long (shaft 2 px wide at about 22% blue, head about 4 x 3 px of `#0400FF`), London about 10 px. Hand placed: 36 in SF for 117 one-way BAI roads and about 100 in London for 252, so no rule reproduces them. The stock JPGs are crops of the same art, so they have them too. The exporter (`hudmap_export.py`) reads the lanes from the records of the BAI (`exported_roads`, `bai_chains`), so converted roads and seamless rows work. The greedy 20 px spacing gives 72 arrows on the SF roads and 66 on the London ones. `hudmapHideArrows` is inverted on purpose: `defaultValue` only works on mesh instance types, and a missing key must keep the arrows.

## Native texture reference

**Textures and slivers:** facade/sliver V runs from the top (v=0 = texture top in the editor; the psdl-viewer uses the flipped convention). Game sliver rule: u = floor(len·s + 0.5), v = (top - y)·s. Stock sliver scales are always positive. Stock city PKGs use byte shaders `0x81` with colours 229/229/0 and shininess 0.25.

## Spline decals

`elements/customElements/decal` uses the generic spline evaluator and road JSON components, API kind `customElement`, points `spline`. `spline.pieces` in exported elements supplies unlifted strip edge pairs; `json_processor.get_decals` passes these as DECAL parts with `strip_pairs=1`. The writer also accepts the older centerline/width input used by existing fixtures. Core component UVs follow the game winding and rounded distance of the first pair; height offset is 0.01 m. Keep projection away from overlay layer 13 to avoid accumulating height on overlapping decals.

`elements/customElements/decalSingle` is the generic point kind (`point` setting: one `center` point, the gizmo on the element with no handle, yaw only, scalable on X and Z, projected on the surface like the spline decal points (`projectionMask` 136), builder wiki `Core-Custom-Elements`, "Point elements"): `lua/decals.single` builds the quad from `ctx.points.center`, `ctx.rotations.center` (euler degrees, applied Z, X, Y; positive X pitch tips the front down) and `ctx.scales.center` (X = width, Z = length), with the strip vertex order of the spline decals (start pair then end pair, U 1 then 0, V = round(length/width) at the end pair, lifted 0.01 m). `json_processor.get_single_decal` recomputes the same four corners from the exported `points.center` (`decal_single_corners`, keep it in sync with the Lua) and emits one `0_DECAL` with `strip_pairs=1`; it warns above 25 m (the game picks the room of midpoint(p0, p2)) and for a mirrored quad. Both decal types use `createMenu.submenu` `DECALS_MENU` and `createMenu.label` (short "Single"/"Spline" in the menu, `ui.label` is the full "Decal (single)"/"Decal (spline)"). Tested by `_test_decals.py` and the builder's `SingleDecals` self-test (`KM2_SELFTEST_FOCUS=splines`).

`converters/generateRailDecals` is non-replacing and creates independent low-poly decal splines across the selected intersection only. `lua/decals.canGenerateRails` controls button availability. Pairing uses `traffic/rails.join_rails`, on the rails as the BAI writer exports them (`bai_writer.Route`). Repeated generation deliberately appends; users delete old decals manually. Migration 3 converts manual city-property decals and removes automatic rail settings without baking them. Update new-city template coreVersion with the core migration version. Focused synthetic checks: `python exporters/psdl/tools/_test_decals.py`; keep stock assets out of fixtures.

The focused builder integration uses `KM2_SELFTEST_FOCUS=splines` with `selftest api <new folder>` (about 6 s windowed). To compare preview geometry/UVs with a real exported PATHSET, use `python exporters/psdl/tools/_test_decals.py --preview <export-json file> <decals.pathset>`.

## Low LOD road textures

`converters/generateLodTexture` (`replace: false`, button in the `ui.json` of the `psdl` road, enabled by `lua/psdl.canGenerateLodTexture`) composes `textureLOD` and sets it on the road through a converter `updates` entry; the file is written outside undo. The layout is measured on the stock `*_lo_f` textures: square, 64x64, type 17, one mip, the road along X, and across it the sidewalk, the half road (`texture1`, its top row at the curb, its bottom row at the center), the divider, then the same bands mirrored, in proportion to their real widths. Along the road each tile is as long as its band is wide, as in `RoadSection` of the psdl-viewer, rounded to whole tiles per texture so that it repeats (so `r6_f` on a 40 m road gives 9 dashes against the 8 of `r6_lo_f`, drawn by hand). The texture covers the whole road only with real sidewalks: flat shoulders are not part of the 0x00 road attribute. The name holds a hash of the pixels, so equal results share one file and a changed result can't show a cached texture.

`_fa` is a darker version of 74 stock textures (roads, sidewalks, decals). The suffix is next to `_ni` in the exe, at `0x1c56a4`, but when the game uses it hasn't been established. The generator writes one when the road texture has one, from the `_fa` of each source (or the plain one). `exporters/psdl/tools/_test_lod_texture.py` has the synthetic checks; builder coverage is `LodTextureGeneration`, `KM2_SELFTEST_FOCUS=splines`. Not checked in game yet.

## Map label previews

Map labels are point custom elements (`mapLabel`, `points.center`) owned by the city-properties singleton `elementContainer`, category `hudmap`, activated by the `CP_HUDMAP` tab. The shared container machinery handles visibility, contextual creation, contents and undo. `lua/map_labels.lua` builds the glyph mesh and its outline from `lua/map_label_font.lua`, generated from the bundled OFL Liberation Sans Bold font by `tools/_generate_map_label_font.py` (development-only fonttools/shapely/mapbox-earcut). The generic `GeometryMesh.color` uses an opaque, unshaded two-sided material. The preview is an editor aid, not a preview of the final map: white text and, 2 cm under it, a black outline (0.05 em, a strip around the edges used by one triangle with round joins at the outer corners, from the clockwise triangles of the glyphs, cached per glyph), with `castShadows` off. From below the ground the outline shows a little through the sharp notches of the letters. The preview alone is raised 5 m; markers and authored controls stay on the ground. The point follows the surfaces (`point.project`), also when loaded. `ctx.parameters` supplies the text, and injected `hudmapMetersPerPixel` supplies scale. The Labels colour is only for the exported maps. The same bundled font is the export default, with four-times label supersampling and 75% size on roam maps. Measured stock style: ink darkens every background by the same factor (black, `LABEL_OPACITY` 0.5, not an opaque grey), default size 6.75 px (cap height 5 px), `LABEL_TRACKING` 0.12 em, markers over labels, JPEGs 4:4:4 at quality 98. `lua/map_labels.lua` keeps its own copy of the size and tracking, so change both. Stock race maps are crops at a fixed zoom per city (roam/race about 0.76 in SF, 0.66 in London, and the London JPGs are squashed vertically against the tiles); the exporter frames each race and uses a fixed 0.75, so label size against the map still differs from stock. An explicit export font override does not replace the bundled preview outlines. Latin/Latin Extended A and common punctuation have generated glyphs; other preview characters use the missing-glyph box while exports retain the full text.

Migration 5 moves legacy `cityProperties.mapLabels` to owned point elements with backups, preserving text, size, angle, map filters and positions. The exporter also accepts legacy standalone JSON. Native HUD tiles and `<city>_hudmap_preview.png` stay label-free; `<city>_hudmap_labels_preview.png` uses All/Roam names. Previews stay outside AR files. Checks: `python exporters/psdl/tools/_test_hudmap.py [builder-export.json] [--stock-archive MM2TEX.AR]`, builder `KM2_SELFTEST_FOCUS=mapLabels`. The optional stock check reads only three known visible words from SF/London JPGs, checking width and cap height within JPEG tolerance (it can't see opacity or letter shapes; the synthetic tests cover the ink, marker order and JPEG sampling). The exact original face cannot be proven from those raster images; describe this as stock-style rendering, not bit-identical reproduction. No stock image or original game font is bundled. Font/source/license details: `fonts/README.md`.
